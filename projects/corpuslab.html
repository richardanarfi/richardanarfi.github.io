CorpusLab

A plausible answer is not enough to tell us whether retrieval found the right evidence. CorpusLab makes that distinction inspectable: define the questions, generate candidate records, establish relevance separately, and measure the resulting system.

Independent research prototype. Fictional enterprise data, clearly labeled illustrative examples, and recorded model experiments.

The measurement problem

What did retrieval miss?

Start from required behavior

A corpus can determine which questions happen to be testable. CorpusLab takes the other direction: define ordinary requests, clearly unsupported requests, and plausible requests with deliberately missing evidence, then generate candidate records inside a coherent fictional organization.

A fixed roster, focal user, and reference clock make entity and temporal conditions explicit. Coverage becomes a design choice rather than an accident.

Generation intent is not a label

A record can miss the condition it was generated to satisfy. It can also be relevant to a different query. The generating query is therefore retained for debugging but removed from judge inputs, along with query categories and executable audit answers.

Every query is judged against its scenario's corpus. Negative and challenging categories do not automatically become empty relevance sets.

Preserve the first-pass evidence

Three models judge in isolated contexts. A separate adjudicator examines split cases; the original votes and short evidence explanations remain available. Unresolved cases and missing responses stay visible instead of being converted into confident negative labels.

Individual judges, majority voting, and adjudication can be compared. Different model families do not by themselves establish independent errors.

Measure two different objects

The inner loop scores returned records against complete panel-reference sets. The outer loop examines the answer's grounding and use of its available evidence. A fluent answer can still conceal missed records.

A keyword baseline, recorded model-generated query plans, and a deliberately regressed executor make the comparison concrete. The injected defect is a teaching condition, not a historical production regression.

The running example

Four records make the distinction visible

This is an illustrative walkthrough, not a reported model-performance result.

Ask for meetings with the product lead last week. One returned record is relevant; another is outside the required date window. A cross-functional meeting generated for a different query is relevant but missing.

The relevant set is R1 and R2; retrieval returns R1 and R3. Precision, recall, and F1 are each 0.50. Treating generation provenance as the label would conceal both a genuine match and a genuine mistake.

Then change the temporal interpretation

The timeline contrasts a previous calendar week with a rolling seven-day look-back. A boundary meeting changes membership because the specification changes, not because its content changes. The workbench keeps this explanation separate from the frozen recorded judgments.

That is the central research lesson: disagreement can reveal a missing decision rule. Adding more judges is not a substitute for deciding what the task is supposed to mean.

Evidence and limits

A transparent prototype, not manufactured certainty

The recorded pilot: a useful warning

The completed run contains 24 queries, 48 fictional records, and 2,448 first-pass model judgments. Its conservative inference accounting was $0.8907 against a $10 cap, including retained uncertainty from interrupted requests.

The injected calendar defect passed the model-reference gate. In an audit query, the reference panel accepted out-of-window records, so the faulty variant could appear better under that reference. I retained the actual result rather than adjusting labels to manufacture a blocked regression.

On 240 verifiable audit pairs, the best individual judge and adjudicated reference both reached 98.75% accuracy, while positive precision was 85%. Those are programmatic checks on a small, imbalanced synthetic subset, not human agreement. The gap is the lesson: high aggregate agreement does not replace an independent check of the specification.

What the recorded experiment supports

The workbench exposes actual model outputs on fictional records, source coverage, reference-label disagreements, retrieval outcomes, answer reviews, and inference accounting. Cached artifacts let another reader recompute the analysis without calling a model.

An executable audit covers only explicitly verifiable entity, action, type, and time constraints. Semantic cases without that reference are not quietly included in an accuracy claim.

What it does not establish

Authored scenarios do not represent production traffic. Model consensus is not human gold, and executable constraints are not a universal semantic oracle. This demo does not reproduce a historical human study.

The annotation view offers browser-local practice labels, not a recruited evaluation cohort. Small-sample comparisons, shared model biases, and deliberate fault injection all limit generalization.
