Model Atlas

Similar scores do not tell us whether models fail on the same examples. I built Model Atlas to test whether shared judging errors predict shared generation failures — and add information beyond aggregate accuracy.

Independent, exploratory research using OpenRouter. Not an official OpenRouter product.

Pilot finding: the judging-to-generation transfer hypothesis remains inconclusive.

Open interactive dashboard Code & methodology
Research question

Beyond another leaderboard

Which failures are shared?

Two models can have the same accuracy while failing on different examples. For a fallback to help, it must succeed where the primary model fails. Model Atlas measures that overlap with task-specific error graphs rather than reducing each model to one average score.

Does behavior transfer between roles?

A model can judge candidate answers or generate an answer itself. I asked whether relationships measured in the first role predict relationships in the second, and whether they improve on a score-only baseline. That transfer is a hypothesis to test, not an assumption.

Separate measurement from selection

Original source prompts are separated into training and test sets before collection. Order-swap probes are excluded from the primary graphs. Fallback choices are selected on training examples and evaluated without reselection on held-out generation examples.

The score-only versus graph-augmented prediction comparison also holds out each model's incident edges. The acquisition counts above are not counts of independent test observations.

Respect dependence and uncertainty

Eight models produce 28 pairs, but those pairs share models and are not independent. The analysis uses source-level bootstrapping and model-node permutations rather than treating every edge as a separate observation.

Inference is conditional on this fixed panel. Task-specific results, missingness, benchmark adaptations, and negative findings remain visible.

Findings

An inconclusive result is still a result

The pilot did not establish useful positive judging-to-generation transfer. It also does not prove that no relationship exists.

−0.142

Small differences are not established improvements

The pooled graph comparison has a node-permutation p-value of 0.502 (four-view BH-adjusted p = 0.669). Adding judging-graph features changed held-out edge-prediction RMSE from 0.0919 to 0.0892. That small reduction is descriptive, not a demonstrated predictive advantage.

The generation-graph fallback reached 85.28% oracle union accuracy versus 84.86% for the accuracy-selected fallback. This assumes a perfect detector that knows when the primary answer is wrong. It is an upper-bound analysis, not an implemented router or ordinary API-error failover. The pilot does not demonstrate a production routing gain.

What I take from this

I would not substitute judging fingerprints for direct generation measurements on the strength of this pilot. The value is a reproducible experiment and a clearer boundary on what the evidence supports, rather than a favorable cluster plot or a new ranking.

Limits and next questions

This is a small, exploratory study, not a preregistered experiment. The selected model panel, adapted public benchmarks, automated scoring, and possible benchmark contamination limit generalization.

A next study would test a broader panel, measure how much diagnostic data is needed, and evaluate fallback decisions with a real error detector under model and workload changes. Those are future experiments, not capabilities demonstrated by this pilot.
